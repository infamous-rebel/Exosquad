Single-process worker with four internal layers and strict inward dependency direction:
- Entry `src/index.ts` bootstraps `WorkerApp`, wires SIGTERM/SIGINT to call `app.stop()`, and catches fatal startup errors via `main().catch(...)`.
- `src/app.ts` owns lifecycle: instantiates `QueueManager` and `IngestionScheduler`, starts them in order, then launches a standalone Fastify server on `config.PORT + 1` exposing `/health` (always ok) and `/health/ready` (503 when any queue reports error).
- `src/scheduler/` implements a lightweight cron-based trigger: `scheduler.ts` (`IngestionScheduler`) polls `prisma.source` every 60s for active sources with `scheduleCron`, enqueues `scheduled-ingest` jobs into the `ingestion` queue using `sourceId` as a deduplicating `jobId`; `cron.ts` ships a self-contained 5-field cron parser supporting wildcards, lists, ranges, steps, and Sunday normalization — no external cron library.
- `src/queues/queue-manager.ts` is the BullMQ facade creating one `Queue` + `Worker` pair per job type sharing a single Redis `ConnectionOptions`, exposing `addJob`/`getStats`/`stop` and attaching shared `completed`/`failed`/`error` listeners via `attachWorkerEvents`.
- `src/processors/` holds pure async handlers (`processIngestionJob`, `processNormalizationJob`) that validate payloads, log with child loggers scoped to `{jobId, jobName, queue}`, and throw on invalid input so BullMQ retry/backoff applies; processors are stubs marked Phase 2.
Dependency direction is strictly index → app → queue-manager + scheduler → processors; no cross-imports between processors.
